[[cloud-volumes-ontap-9-19-1-in-azure]]
=== Azure의 Cloud Volumes ONTAP 9.19.1

이제 NetApp Console을 사용하여 Azure에서 Cloud Volumes ONTAP 9.19.1의 일반 출시(GA) 버전을 배포하고 관리할 수 있습니다.

콘솔은 2026년 8월부터 AWS 및 Google Cloud에서 Cloud Volumes ONTAP 9.19.1을 지원합니다.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 릴리스 노트"^]



[[azure-encryption-at-host-for-cloud-volumes-ontap]]
=== Cloud Volumes ONTAP용 Azure 호스트 암호화

Cloud Volumes ONTAP 9.19.1 GA부터 필수 조건을 충족하는 새로운 Azure 단일 노드 및 고가용성(HA) 배포에 대해 Azure 호스트 암호화가 기본적으로 활성화됩니다. 이 기능은 데이터가 호스트에 기록되고 호스트에서 읽힐 때 임시 디스크 및 관련 호스트 수준 캐시 등 VM을 호스팅하는 물리적 서버의 데이터를 암호화합니다.

Azure에 Cloud Volumes ONTAP을 배포하기 전에 환경이 다음 필수 조건을 충족하는지 확인하십시오.

* 해당  `EncryptionAtHost` 기능이 Azure 구독에 등록되었습니다.  https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft 설명서: 호스트에서 암호화 활성화"^]을(를) 참조하십시오.
* 선택한 VM 인스턴스 유형은 Azure 지역의 호스트에서 암호화를 지원합니다.  https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft 설명서: 지원되는 VM 크기 찾기"^]을(를) 참조하십시오.


다음 사항에 유의하십시오:

* 추가 구성이 필요하지 않습니다.
* 이러한 필수 조건을 충족하지 못하면 Cloud Volumes ONTAP 배포에 대해 호스트에서의 Azure 암호화가 활성화되지 않습니다.
* 호스트 암호화는 Azure에만 적용되며 AWS 또는 Google Cloud에는 적용되지 않습니다.


Microsoft 문서: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Azure 포털을 사용하여 호스트 암호화를 통해 종단 간 암호화를 활성화하십시오."^]



[[backend-network-encryption-on-cloud-volumes-ontap-clusters-in-azure-and-google-cloud]]
=== Azure 및 Google Cloud의 Cloud Volumes ONTAP 클러스터에서 백엔드 네트워크 암호화

Cloud Volumes ONTAP 9.19.1 이상 버전은 Azure 및 Google Cloud의 고가용성(HA) 구성에 대한 백엔드 클러스터 네트워크 암호화를 지원합니다.

클러스터 네트워크 암호화를 활성화하면 클러스터 성능에 영향을 미칠 수 있습니다. 이 기능을 활성화하기 전에 주의를 기울이고 환경에서 추가 오버헤드를 수용할 수 있는지 확인하십시오.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Cloud Volumes ONTAP 클러스터에서 백엔드 네트워크 암호화를 활성화합니다."^]



[[ability-to-reduce-disruptions-during-azure-scheduled-maintenance]]
=== Azure 예약 유지 관리 중 중단을 줄일 수 있는 기능

예정된 유지 관리 중에 Azure는 Cloud Volumes ONTAP HA 쌍의 VM을 잠시 일시 중지할 수 있습니다. ONTAP은 이 일시 중지를 노드 장애로 인식하고 스토리지 작업을 파트너 노드로 이동한 다음 VM이 다시 시작될 때 다시 이동시킬 수 있습니다(테이크오버 및 반환). 이 프로세스는 노드 장애가 없는 경우에도 활성 클라이언트 연결을 중단시킬 수 있습니다.

Cloud Volumes ONTAP 9.19.1 이상 버전에서는 Azure 예약 유지 관리로 인해 HA 쌍이 일시 중단되는 동안 자동으로 테이크오버 및 기브백을 시작하지 않고 계속 작동하도록 하는 선택적 설정을 활성화할 수 있습니다.


NOTE: 이 기능은 Cloud Volumes ONTAP 9.19.1 버전에서 공개 미리 보기로 제공됩니다.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Azure 유지 관리 중 Cloud Volumes ONTAP HA 쌍의 중단을 방지합니다."^]
