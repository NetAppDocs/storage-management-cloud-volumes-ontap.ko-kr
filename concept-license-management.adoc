= Cloud Volumes ONTAP의 BYOL 라이센싱에 대해 알아보십시오
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
BYOL(Bring-Your-Own License)은 클라우드 마켓플레이스 구독을 사용하는 대신 NetApp에서 직접 라이선스를 구매하는 Cloud Volumes ONTAP 요금 모델입니다.

BYOL(Bring Your Own License)은 가용성 제한이 적용될 수 있지만 표준 모드 및 프라이빗 클라우드 모드 배포에서 사용할 수 있습니다. BYOL 라이선스는 NetApp Console의 *라이선스 및 구독* 섹션에 있는 *직접 라이선스*에서 관리할 수 있습니다. 각 라이선스는 회사 및 특정 NetApp 지원 사이트 자격 증명과 연결됩니다.

* NetApp은 유효한 마켓플레이스 구독이 있는 표준 모드 배포에 대해 BYOL 라이선스의 구매, 연장 및 갱신을 제한합니다. 자세한 내용은 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/whats-new.html#restricted-availability-of-byol-licensing-for-cloud-volumes-ontap["Cloud Volumes ONTAP 에 대한 BYOL 라이선싱의 제한된 가용성"^]을 참조하십시오.
* NetApp은 노드 기반 라이선스를 단계적으로 폐지하고 용량 기반 라이선스로 전환하고 있습니다. 노드 기반 라이선스는 일부 USPS 고객 구축 환경 및 중국 내 구축 환경 등 일부 기존 구축 환경에 한해 계속 사용할 수 있습니다. 자세한 내용은 https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html#end-of-availability-of-node-based-licenses["노드 기반 라이선스 제공 종료"^]을 참조하십시오.




[[byol-deployment-modes]]
== BYOL 배포 모드

[role="tabbed-block"]
====
.표준 모드 배포
--
* BYOL 대신 NetApp은 소비량 청구를 위해 연간 또는 사용량 기반 요금제(PAYGO) 마켓플레이스 구독 방식을 선호합니다.
* 표준 모드 배포에서는 일반적으로 노드 기반 라이선스 대신 용량 기반 라이선스를 사용합니다. 기존 표준 모드 배포 중 노드 기반 라이선스를 사용하는 경우는 극히 드뭅니다.


--
.프라이빗 모드 배포
--
* 프라이빗 모드 배포는 마켓플레이스 구독을 사용할 수 없으므로 BYOL 라이선스에 전적으로 의존합니다.
* 새로운 배포 환경에서는 노드 기반 라이선스 대신 용량 기반 Essentials 패키지를 사용하십시오. 노드 기반 라이선스는 일부 기존 프라이빗 모드 배포 환경에서 사용됩니다.


--
====


[[compare-byol-license-types-in-private-mode]]
=== 프라이빗 모드에서 BYOL 라이센스 유형 비교

다음 표는 프라이빗 모드에서 용량 기반 라이선스와 노드 기반 라이선스 간의 차이점을 요약한 것입니다.

[cols="25,37,38"]
|===
| 기능 | 용량 기반 라이센스 | 노드 기반 라이센스 


| 배포 지원  a| 
새로운 프라이빗 모드 배포는 용량 기반 라이선스, 특히 Essentials 패키지만 지원합니다.
 a| 
새로운 프라이빗 모드 배포는 노드 기반 라이선스를 지원하지 않습니다. 기존 노드 기반 배포 중 제한된 수만 노드 기반 라이선스를 계속 사용할 수 있습니다.



| 구입  a| 
NetApp에서 용량 기반 BYOL Essentials 패키지를 구매하고 배포 중에 시스템에 할당하십시오.
 a| 
노드 기반 라이센스를 사용하는 기존 프라이빗 클라우드 모드 배포 환경이 있는 경우 NetApp에서 Essentials 패키지를 구매하여 용량 기반 라이센스로 전환할 수 있습니다.



| 용량  a| 
최초 500GiB 사용량은 라이선스 요금에 포함되지 않습니다. 워크로드 요구 사항이 증가함에 따라 추가 패키지를 구매할 수 있습니다.
 a| 
노드 기반 라이센스는 단일 노드 또는 HA 쌍에 대해 최대 368 TiB의 용량을 제공합니다. Cloud Volumes ONTAP 시스템에 368 TiB를 초과하여 할당하려면 여러 라이센스를 구매하십시오. 예를 들어, 라이센스 2개는 최대 736 TiB를 제공하고 라이센스 4개는 최대 1.4 PiB를 제공합니다.



| 범위  a| 
용량 기반 라이선스는 Cloud Volumes ONTAP 시스템 전체에서 공유되는 용량 풀을 활용합니다. 스토리지 요구 사항이 변경되면 사용 가능한 용량을 재분배할 수 있습니다.
 a| 
각 노드 기반 라이선스는 하나의 Cloud Volumes ONTAP 시스템에 적용되며 해당 시스템에 고정된 용량을 제공합니다.



| 양도 가능성  a| 
용량 기반 라이선스는 Console 계정과 연결됩니다. 해당 계정으로 생성된 시스템은 라이선스 용량과 일련 번호를 공유할 수 있습니다. 예를 들어, 5TiB 라이선스는 각각 2.5TiB 용량의 시스템 두 대를 지원하거나 5TiB 용량의 시스템 한 대를 지원할 수 있습니다. Console에서 라이선스 일련 번호를 확인하고 동일한 계정으로 여러 시스템에 동일한 라이선스를 할당할 수 있습니다.
 a| 
노드 기반 BYOL 라이선스는 기존 시스템을 삭제하고 해당 라이선스를 사용하여 새 시스템을 생성함으로써 이전할 수 있습니다. 클라우드 제공업체 간에는 _클라우드에 구애받지 않는_ 일련 번호만 사용 가능합니다. 이러한 일련 번호는 _908xxxx_ 접두사로 시작합니다.

|===

[[renew-a-byol-license]]
=== BYOL 라이선스 갱신

NetApp 담당자에게 문의하여 BYOL 라이선스를 갱신하십시오. 콘솔에서 갱신된 라이선스를 자동으로 가져와 Cloud Volumes ONTAP 시스템에 설치합니다.

콘솔이 보안 인터넷 연결을 통해 라이선스 파일에 액세스할 수 없는 경우 라이선스 파일을 다운로드하고 link:task-manage-node-licenses.html["Console에 수동으로 업로드합니다"].

Console과 연결된 NetApp Support Site 자격 증명을 관리하려면  https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html["NetApp Console과 연결된 NSS 자격 증명을 관리합니다."^]을(를) 참조하십시오.



[[respond-to-an-expiration-warning]]
=== 만료 경고에 응답

콘솔은 노드 기반 라이선스 만료 30일 전과 만료일에 경고 메시지를 표시합니다. Cloud Volumes ONTAP 시스템을 선택하여 경고 메시지를 확인하고 라이선스를 갱신하십시오.

image:screenshot_warning.gif["스크린샷: 경고 아이콘이 포함된 Cloud Volumes ONTAP 시스템을 보여줍니다.  아이콘은 작업이 필요함을 나타냅니다."]

조직 관리자 또는 계정 관리자이고 해당 옵션을 활성화한 경우 콘솔에서 Cloud Volumes ONTAP 보고서에 라이선스 만료 경고를 포함하고 이메일로도 전송합니다.

라이선스가 만료되기 전에 갱신하지 않으면 Cloud Volumes ONTAP 시스템이 종료됩니다. 라이선스를 갱신하지 않고 시스템을 다시 시작하면 시스템이 다시 종료됩니다.
